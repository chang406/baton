# Baton 사용법 (치트시트)

외울 필요 없습니다. 모르겠으면 에이전트에게 **"사용법"**이라고 물어보세요.

## 매일 쓰는 것

| 하고 싶은 것 | Claude Code | Codex |
| --- | --- | --- |
| 새 작업 시작 | `/task-start 로그인 후 원래 페이지로 이동하게` | "새 작업: 로그인 후…" |
| 이어서 하기 (새 세션, 에이전트 교체) | `/task-resume` | "이어서 하자" |
| 멈추기 / 넘기기 | `/task-handoff` | "넘길게" |
| 끝내기 | `/task-finish` | "끝" |

Claude Code에서는 `/task`까지만 치면 목록이 나옵니다.

**Codex를 처음 열 때:** "Review hooks"가 뜨면 baton 상태 훅(`scripts/baton/status.mjs`)인지 보고 신뢰(Trust)를 고르세요. 그다음부터 세션을 열 때 화면에 "Loading Baton status"가 잠깐 보이고, 에이전트가 진행 상황을 미리 알고 시작해요.

**세션 시작 상태 요약:** Claude Code와 Codex 모두 상태 요약은 화면에 따로 뜨지 않고 에이전트에게만 전달돼요(에이전트는 먼저 말을 걸지 않아요). 잘 전달됐는지 보려면 "세션 시작 때 받은 baton 상태 보여줘"라고 물어보세요.

**한도에 걸려 갑자기 끊겼을 때:** "넘길게"를 못 했어도 괜찮아요. 다른 에이전트(또는 한도가 풀린 뒤)에서 "이어서 하자"라고만 하세요. 끊긴 세션 기록에서 마지막 요청·답변·고친 파일을 뽑아 인계 초안을 만들고, 확인받은 뒤 이어서 해요.

**다른 컴퓨터에서 이어서 할 때:** 넘길 때 "다른 컴퓨터에서 이어서 할 거야"라고 하면 작업 브랜치를 올려(push) 줘요. 받는 컴퓨터에서는 "이어서 하자"라고 하면 먼저 받아오기(fetch)를 제안해요. 진행 중인 작업 기록은 작업 브랜치에 있어서, 받아오지 않으면 "작업 없음"으로 보일 수 있어요.

## 끝낼 때 검증

중간·큰 작업을 "끝"낼 때는 **검증 담당**이 따로 확인해요. 보안·성능 쪽을 건드렸으면 알려주고, 별도 도구 `audit`이 설치돼 있으면 정밀 점검을 할지 물어봐요.

## 큰 기획이 필요할 때만 (L 크기)

1. 채팅 앱 프로젝트에서 이야기한다.
2. "정리해줘" → 나온 코드 블록을 복사한다.
3. Claude Code에서 `/task-start` 뒤에 붙여넣는다.
4. 에이전트가 의도 요약과 계획을 보여주면 읽어보고 승인한다. (plan mode: Shift+Tab)

작은 작업과 기능 하나 정도(S, M)는 채팅을 거치지 않고 바로 CLI에 말하면 됩니다.

## 에이전트가 알아서 하는 것

- 세션 시작 시 현재 상태 요약 (Claude Code는 자동으로 표시)
- 작업 중 ACTIVE.md 갱신, 코드와 함께 커밋
- 실패한 방법 기록, 다음 에이전트가 반복하지 않게 함
- 위험 작업(운영 데이터, 배포·출시, main 병합, GitHub 업로드) 전에 멈추고 승인 요청
- 커밋 전 비밀값(API 키, 비밀번호) 검사, 기록 문서에 비밀값·개인정보 안 남기기

## 직접 확인하고 싶을 때

- 그냥 에이전트에게 물어보세요: "지금 상태 어때?", "검증 돌려줘"
- baton 설치가 깨지지 않았는지: "baton 진단해줘" (직접 하려면 `node scripts/baton/doctor.mjs` — 모두 [x]면 정상, [!]는 고치면 좋은 경고)
- 인계·이어받기를 숫자로 보기: "baton 기록 보여줘" (직접 하려면 `node scripts/baton/stats.mjs`). 따로 기록할 필요 없어요. Git과 세션 기록에서 알아서 셉니다.

## 이 파일들, 지우거나 .gitignore하지 마세요

baton 파일은 프로젝트 코드와 상관없어 보여도 **작업 방식 설정**이에요. `.editorconfig`나 `.github/` 폴더처럼 Git에 같이 올라가야 해요.

- 다른 에이전트(Codex 등)나 다른 컴퓨터는 Git에 올라간 `tasks/ACTIVE.md`를 보고 작업을 이어받아요. 빼면 이어받을 게 없어요.
- 한 컴퓨터에서 baton을 업데이트하고 push하면 다른 컴퓨터는 pull만 하면 돼요. 빼면 컴퓨터마다 따로 해야 하고, 새로 받은(clone) 곳에서는 세션 시작 훅이 오류를 내요.
- `tasks/archive/`는 끝난 작업 기록이에요. 오래된 것 같아도 지우지 마세요.

**반대로 Git에 올리면 안 되는 개인 설정** (.gitignore에 들어 있어야 해요)

| 파일 | 무엇 |
| --- | --- |
| `.claude/settings.local.json` | 이 컴퓨터에서만 쓰는 Claude Code 설정 (허용한 명령 목록 등) |
| `CLAUDE.local.md` | 나만 보는 Claude 메모 |
| `.claude/worktrees/` | Claude Code가 작업 사본을 만드는 임시 폴더 |
| `.env`, `.env.*` 등 | 비밀값 (원래부터 제외) |

작업을 시작하거나 끝낼 때도 같은 이름 브랜치·기록이 있는지 먼저 확인하고, 겹치면 멈추고 물어봐요.

헷갈리면 "baton 진단해줘"라고 하세요. 빠진 게 있으면 알려줘요.

## 파일 위치

- `tasks/STATUS.md` — 프로젝트 장기 기억, 지켜야 할 규칙
- `tasks/ACTIVE.md` — 지금 하는 작업
- `tasks/archive/` — 끝난 작업 기록 (지우지 않기)
- `AGENTS.md`, `CLAUDE.md` — 에이전트 작업 규약. `<!-- baton:start -->` ~ `<!-- baton:end -->` 블록 안은 baton이 관리하고(업데이트 때 바뀜), 블록 밖은 이 프로젝트의 규칙이에요. 직접 쓸 규칙은 블록 밖에 쓰세요. baton 블록은 영어로 쓰여 있어요(Codex가 기본으로 읽는 양이 32KB라, 한국어보다 크기가 절반 정도인 영어로 줄였어요). 에이전트는 항상 한국어로 답해요. 블록 밖 규칙은 한국어로 쓰셔도 돼요.
- `docs/baton/chat-project-instructions.md` — 채팅 앱 프로젝트 지침
