# baton — 에이전트끼리 바통 넘기기

## 처음 한 번만 (컴퓨터에서 딱 한 번)

1. 저장소를 `~/harness`에 받는다 (Windows: `C:\Users\<이름>\harness`). 이 폴더는 `~/harness/baton`이다.
2. 그 폴더에서 Claude Code를 켜고 이렇게 말한다:
   > GLOBAL_SETUP_FOR_AGENT.md 읽고 설정해줘

이제 끝. 앞으로 코드 프로젝트 폴더에서 Claude Code를 켜고 **아무 말이나** 하면, baton이 없을 때 Claude가 **"설치할까요?"** 하고 물어봐요. **"응"**만 하면 됩니다.
Next.js, Python, Unity 등 프로젝트 종류에 맞게 알아서 조정하고, Git이 없으면 만들지 물어봐요.
아직 아무것도 없는 새 폴더라면 "새 프로젝트 시작하자"라고 말하면 돼요. 기술을 정하기 전이어도 기록 기능부터 설치하고, 나중에 정해지면 알아서 맞춰요.

## 매일 쓰는 말

- 일 시작: **"새 작업: (하고 싶은 거)"**
- 다시 켰을 때 / Codex로 바꿨을 때: **"이어서 하자"**
- 그만할 때: **"넘길게"**
- 다 끝났을 때: **"끝"**
- 모르겠으면: **"사용법"**
- 인계·이어받기 숫자 보기: **"baton 기록 보여줘"**
- baton 새 버전 받았을 때(프로젝트 안에서): **"baton 업데이트해줘"**
- 빠진 프로젝트가 있으면: **"바탕화면 아래에서 baton 찾아줘"** (지정한 폴더 아래만 찾고, 찾은 건 기억해요)
- 어느 프로젝트에 깔려 있고 뭐가 낡았는지 한 번에 보고 업데이트: **"baton 전체 점검해줘"** (아무 폴더에서나. 고른 프로젝트만 업데이트하고, 확인이 필요한 줄은 그 자리에서 보여 주고 물어봐요. main에 합치는 것도 승인하면 거기서 끝내요)
- 프로젝트 종류가 바뀌었거나 정해졌을 때: **"baton 다시 맞춰줘"** (보통은 알아서 물어봐요)

> **기존 문서를 고쳐 쓰지 않아요.** AGENTS.md·CLAUDE.md가 이미 있으면 맨 위에 baton 블록(`<!-- baton:start -->` ~ `<!-- baton:end -->`)만 끼우고, baton은 그 블록 안만 관리해요. 블록 밖이 프로젝트 고유 규칙이에요. baton의 상태 기록은 `tasks/STATUS.md`라서 기존 STATUS.md와도 겹치지 않아요. 새 프로젝트는 처음부터 설치하면 가장 깔끔하고, 진행 중인 프로젝트에 설치해도 괜찮아요.

> **겹치면 먼저 멈추고 물어요.** 설치·업데이트·작업 시작·끝내기 전에 사전 검사가 같은 이름 파일, 이미 있는 브랜치, 진행 중인 병합, 커밋 안 된 변경 등을 먼저 확인해요. 걸리는 게 있으면 아무것도 바꾸기 전에 한 번에 보여 주고 물어봐요.

> **프로젝트에 생기는 baton 파일은 지우거나 .gitignore하지 마세요.** 코드와 상관없어 보여도 작업 방식 설정이에요. Git에 올라가 있어야 Codex나 다른 컴퓨터가 이어받고, 한 번 업데이트한 걸 pull로 나눠 받을 수 있어요. 대신 개인 설정(`.claude/settings.local.json`, `CLAUDE.local.md`, `.claude/worktrees/`)은 설치할 때 .gitignore에 넣어 줘요. 자세한 건 설치된 프로젝트의 `docs/baton/README.md`.

## 시험 (harness를 고칠 때)

`node --test "tests/*.test.mjs"` — 임시 폴더의 가짜 프로젝트로 설치·업데이트·사전 검사·보존 확인·sync·audit 설치를 확인해요(실제 `~/.claude`나 프로젝트는 건드리지 않음). GitHub에 push하면 Linux·Windows에서 자동으로 돌아요(`.github/workflows/test.yml`).

<details>
<summary>안에 든 것 (몰라도 됨)</summary>

| 파일 | 역할 |
| --- | --- |
| `GLOBAL_SETUP_FOR_AGENT.md` | 전역 설정에 GLOBAL_RULES.md를 불러오는 한 줄을 넣는 지침 |
| `GLOBAL_RULES.md` | "baton 없으면 먼저 물어보기" 규칙. 규칙을 바꿀 땐 이 파일만 고치면 됨 |
| `INSTALL_FOR_AGENT.md` | 프로젝트 하나에 baton을 설치하는 지침 (프로젝트 종류별 조정 포함) |
| `sync.mjs` | 여러 프로젝트 일괄 점검·업데이트 (프로젝트에 복사되지 않음). 사용자가 직접 쓴 줄이 있는 파일은 건너뜀 |
| `preserve-check.mjs` | 설치·업데이트 뒤 원래 있던 문서 줄이 사라지지 않았는지 확인 (프로젝트에 복사되지 않음) |
| `cost.mjs` | 토큰 점검: baton이 세션마다 고정으로 넣는 양과 필요할 때만 넣는 양(추정), 세션 기록의 첫 요청 입력 토큰 실측 비교. 읽기 전용 (프로젝트에 복사되지 않음) |
| `place.mjs` | 설치 때 파일 배치: 없는 파일만 복사, AGENTS.md·CLAUDE.md엔 블록만 끼우고, settings.json·.codex/hooks.json엔 훅만 추가 (프로젝트에 복사되지 않음) |
| `blocks.mjs` | baton 블록 찾기·교체, 옛 형식 전환 (place·sync가 함께 씀) |
| `preflight.mjs` | 설치·업데이트·전역 설정 전 사전 검사. 겹치는 이름이나 문제될 상태가 있으면 [멈춤]으로 알리고, 에이전트는 멈추고 물어요 (프로젝트에 복사되지 않음) |
| `known.mjs` | 위 둘이 함께 쓰는 판정: baton 원본의 모든 과거 버전에 없는 줄 = 사용자가 쓴 줄 |
| `files/` | 프로젝트에 복사되는 파일들 (AGENTS.md, STATUS.md, tasks/, 슬래시 명령, 상태 확인·진단·사용 기록·비밀값 검사 스크립트, 검증 담당 서브에이전트, 채팅 앱 지침) |

</details>

> 보안·성능 정밀 점검은 별도 도구(`audit`)예요. 설치돼 있으면 baton이 필요할 때 권해줘요.
