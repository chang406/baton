# baton

[English](README.md)

**Claude Code와 Codex를 오가며 일할 때, 한 세션이 끝난 자리에서 다음 세션이 바로 이어받게 해 주는 인계 키트.**

> **상태: 잠정 종료 (2026-11).** 작성자가 자기 작업에 쓰려고 만들었고, 지금은 새 기능을 더하지 않는다. 쓰다가 생긴 문제만 고친다. 이슈와 PR은 읽지만 답이나 반영을 약속하지 않는다.

20달러 요금제 두 개(Claude Pro, ChatGPT Plus)로 코딩하면 5시간 한도에 자주 걸린다. 그때마다 다른 도구로 넘어가면 새 세션은 앞의 일을 모른다. 코드를 직접 읽지 않는 사람은 무엇이 어디까지 됐는지 스스로 복원하기도 어렵다. baton은 그 사이를 이어 준다.

- 대상: AI로 앱을 만들지만 코드를 직접 읽지는 않는 사람. 응답은 한국어로 한다.
- 같이 들어 있는 것: **audit**, 보안·성능 정밀 점검 도구. baton 없이도 쓸 수 있다.

## 어떻게 동작하나

| 장치 | 하는 일 |
| --- | --- |
| `tasks/ACTIVE.md` | 지금 작업의 인계 문서. 요청 원문, 완료 기준, 현재 상태, 실패한 시도, 정확한 다음 한 걸음 |
| `tasks/STATUS.md` | 프로젝트의 장기 기억과 금지 사항 |
| Git Wins | 기록과 실제 코드가 어긋나면 Git을 믿는다. 브랜치 불일치, 기록 이후의 코드 커밋, 커밋 안 된 변경 등 4가지를 세션 시작 때 검사해 알린다 |
| 비상 인계 | 한도에 걸려 "넘길게"를 못 하고 끊긴 세션을 다음 세션 시작 때 스스로 알아챈다. Claude·Codex가 이미 저장해 둔 세션 기록에서 1.5KB 이하 초안을 만든다(비밀값 가림). 평소 추가 비용은 0 |
| 멈추고 묻기 | 설치·업데이트·배포·main 병합·비밀값처럼 되돌리기 어려운 일 앞에서는 사전 검사가 멈추고 한 번에 묻는다 |
| 사용자 줄 보존 | 업데이트는 `<!-- baton:start -->` 블록 안만 바꾼다. baton 원본의 어느 과거 버전에도 없던 줄은 사용자가 쓴 줄로 보고 건드리지 않는다 |

Claude Code와 Codex CLI 둘 다 같은 파일을 읽는다. 세션 시작 훅은 두 도구 모두에 넣는다.

## 설치

처음 한 번만 하면 된다.

```bash
git clone https://github.com/chang406/baton ~/harness
```

Windows는 `C:\Users\<이름>\harness`에 받는다. 그다음 `~/harness/baton` 폴더에서 Claude Code를 켜고 이렇게 말한다.

> GLOBAL_SETUP_FOR_AGENT.md 읽고 설정해줘

그 뒤로는 baton이 없는 프로젝트에서 Claude Code를 켜면 **"설치할까요?"**라고 먼저 묻는다. 묻지 않게 하려면 프로젝트 맨 위에 빈 `.baton-skip` 파일을 둔다.

audit은 `~/harness/audit` 폴더에서 "SETUP_FOR_AGENT.md 읽고 설치해줘"라고 하면 된다.

## 매일 쓰는 말

| 말 | 하는 일 |
| --- | --- |
| "새 작업: …" | 작업 크기(S/M/L)를 정하고 작업 브랜치와 인계 문서를 만든다 |
| "이어서 하자" | 인계 문서와 Git을 맞춰 보고 다음 한 걸음부터 이어간다. 다른 도구로 바꿨을 때도 같다 |
| "넘길게" | 인계 문서를 갱신하고 커밋한다 |
| "끝" | 별도 검증 담당이 확인한 뒤 마무리한다 |
| "사용법" | 쓰는 말을 다시 보여 준다 |

더 많은 말과 파일 설명은 [baton/README.md](baton/README.md), [audit/README.md](audit/README.md).

## 판단 원칙

- 기본은 에이전트 하나와 좋은 문맥이다. 나누는 데는 이유가 있어야 한다(독립 조사, 한 문맥에 안 들어가는 분량, 만든 쪽과 검증하는 쪽의 분리).
- 쓰는 쪽은 한 명이다. 순차적인 작업을 쪼개면 오히려 나빠진다.
- 꼭 지킬 규칙은 훅으로, 절차는 지침 파일로. 글로만 쓴 규칙은 긴 작업에서 밀린다.
- 규칙과 고전적인 방법으로 풀리는 일에 AI를 붙이지 않는다. baton의 판정(Git Wins, 사용자 줄, 비상 인계 초안)은 전부 AI 없이 스크립트가 한다.
- 측정 없이 채택하지 않는다.

## 시험

```bash
node --test "tests/*.test.mjs"
```

Node 22, 추가 설치 없음. 임시 폴더의 가짜 프로젝트로 설치·업데이트·옛 버전 전환·사전 검사·비상 인계·audit 설치와 읽기 전용 가드를 확인한다(48개). GitHub Actions에서 Linux와 Windows로 돈다.

## 한계

솔직하게 적는다. 이 저장소는 한 사람이 한 달 남짓 자기 작업에 쓰며 다듬은 도구이고, 검증된 제품이 아니다.

**검증 범위**
- **실사용자는 작성자 한 명이다.** 작성자의 프로젝트 몇 개(Unity 게임, 웹 앱 등)에서만 써 봤다. 다른 사람이 설치부터 해 본 적은 없다.
- **인계가 실제로 얼마나 잘 되는지는 재지 않았다.** 이어받은 세션이 몇 번 만에 제대로 일을 이어 갔는지, 비상 인계 초안이 얼마나 맞았는지 같은 숫자가 없다. `baton 기록 보여줘`(stats.mjs)로 셀 수는 있지만 모아서 정리하지 않았다.
- **baton이 매 세션 쓰는 토큰은 추정치만 있다.** `cost.mjs`로 잴 수 있지만 실측은 하지 않았다.
- **audit의 정확도는 직접 만든 작은 벤치(Node/Express API, 파일 27개, 심어 둔 문제 11개와 미끼 5개)에서만 쟀다.** 4번 돌려 4번 모두 11/11, 오탐 0이었다([채점 기록](measurements/audit-bench-answer-key.md)). 외부 기준(OWASP 벤치 등)으로는 재지 않았다.
- **시험은 Linux·Windows에서만 돈다.** macOS는 확인하지 않았다. 작성자는 Windows를 쓴다.

**동작의 한계**
- **사용자에게는 한국어로만 답한다.** 에이전트 지침(AGENTS.md 블록)은 영어지만 답은 한국어로 하게 돼 있다.
- **설치 위치가 `~/harness`로 고정이다.** 다른 곳에 받으면 지침 속 경로가 맞지 않는다.
- **Claude Code와 Codex만 지원한다.** Cursor, Gemini CLI 등은 안 된다.
- **사용량 한도를 미리 알려 주지 않는다.** 끊긴 뒤에 다음 세션이 알아챈다. 세션 기록은 그 컴퓨터에만 있어서 다른 컴퓨터에서는 비상 인계 초안을 못 만든다.
- **Codex에서는 "끝"의 검증이 독립적이지 않다.** Claude Code는 별도 검증 담당(서브에이전트)이 확인하지만, Codex용 검증 담당은 없어서 같은 세션이 체크리스트를 따르고 "독립 검증 아님"으로 표시한다.
- **지켜야 할 규칙 대부분이 글로 된 지침이다.** 훅으로 강제하는 것은 세션 시작 상태 표시와 audit의 읽기 전용 가드뿐이다. 긴 세션에서 에이전트가 지침을 놓칠 수 있다.
- **audit의 읽기 전용 훅은 실제 Claude Code에서 도는지 아직 확인하지 않았다.** 시험은 가드 스크립트 자체만 확인한다.
- **Git이 필요하다.** 인계와 판정이 브랜치와 커밋 위에 서 있다. Git을 모르는 사용자는 꼬였을 때 직접 풀기 어렵다.

**비슷한 도구**
- 세션 인계를 `HANDOFF.md` 한 장으로 하는 스킬은 여럿 있다. 한도로 끊긴 세션을 저장된 기록에서 복구하는 도구도 있다([claude-handoff](https://github.com/Vasilispapg/claude-handoff) 등). baton이 다른 점은 세션 시작 때 스스로 알아채는 것, 기록과 Git이 어긋나면 알리는 것, 업데이트 때 사용자 줄을 지키는 것 정도다. 비교는 [docs/research](docs/research).

이 저장소의 이력은 공개 시점에서 새로 시작했다. 그 전 버전의 줄은 `baton/known-history.json`에 모아 두어 옛 설치본도 알아본다.

## 앞선 시도

baton은 세 번째 시도다. 앞의 두 프로젝트는 로컬 서버로 세션끼리 잇는 쪽이었다(캐릭터와 말투 기억을 넣은 멀티 pane 작업 환경 → 요청 전달만 남긴 relay). 둘 다 멈췄고, 거기서 배운 것이 서버 없이 파일과 Git으로 가는 지금 설계로 이어졌다. 코드와 회고: [chang406/myade-relay](https://github.com/chang406/myade-relay).
